Why I made my agents say I don't know

October 2026

Agents sound confident when they are guessing. That is the whole problem. In a demo it is funny. In production, a confident wrong answer gets copied into a ticket, a customer reply, a decision. No answer would have been cheaper.

So I built a small set of source-first guardrails that any team can add to their agent setup. Three rules, all about one thing: the agent has to earn the right to answer.

First, declare before you answer. Before the agent produces anything factual, it has to state what it knows, what it is inferring, and what it cannot verify. It answers from the declared knowledge only. When the unverifiable part gets too big, it refuses. A clean refusal is a feature, not a failure.

Second, look it up where the human points. When there is a gap, the agent does a targeted lookup against the source the user names: a document, a repository, a record, a page. If the answer is not in that source, the agent says so, in a structured way, instead of improvising around the gap.

Third, verify your own work. Agents love to report done. This rule makes an agent show exactly what it checked, what scope it covered, and what it could have missed, before it is allowed to say done, clean, or fixed. Completion is a claim, and claims get audited.

None of this makes an agent smarter. It makes an agent trustworthy, which is a different and harder thing. Teams do not stop using agents because the model got a fact wrong. They stop because they cannot tell when it is wrong. Guardrails you can read are how you fix that.
