Source-first guardrails

Guardrails

Three rules so agents answer from sources

A small set of guardrails I wrote, published for other teams to add to their own agents. They exist because agents sound confident when they are guessing, and a confident wrong answer costs more than no answer.

  • Declare before answeringThe agent states what it knows, what it is inferring, and what it cannot verify, before it answers. Past a point, it refuses.
  • Look it up at the sourceWhen there is a gap, the agent checks the source you name: a document, a codebase, a record. If the answer is not there, it says so instead of improvising.
  • Verify your own workBefore an agent can report done or fixed, it has to show what it checked, what scope it covered, and what it might have missed.

Cost

Model routing, so cost stays honest

Large file reads and document fetches are the quiet budget killer in agent work. I built a routing step that sends those reads to a small, fast model first: it extracts the content into compact notes, and the main model reasons over the notes. The full file never enters the expensive context, and the answers hold up. Before I shared it, I ran a fidelity check across task types to make sure the summaries were not losing what matters.
